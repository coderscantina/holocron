# Kit implementation contract

This document is the production frontend handoff for [the technical briefing](technical-briefing.md). It specifies how to adapt Kit to Holocron. The briefing owns product scope, metrics, privacy, storage, and compatibility. This document owns frontend integration and observable interface behavior. Read it before building the shell, exploration controls, tables, charts, saved views, or account screens.

The source observations below describe inspected code on October 3, 2026. Requirements describe the proposed Holocron implementation. Neither the source observations nor the [overview example](../examples/overview/index.html) establish that a production dashboard exists. The example is a visual reference with illustrative data.

## Extraction boundary

Build on Vue 3, TypeScript, Vue Router, Tailwind, Kit's shadcn/Reka primitives, Vue Query and VueUse. Use plain Vite. Inspect and pin the installed dependency versions before adapting component APIs. Keep imports explicit for composables and application services. Vue template comments are omitted in adapted files.

Kit's [API client](/Users/mwallner/Development/products/kit/resources/js/api/client.ts) primes `/auth/csrf-cookie`, retries Laravel 419 responses, adds Echo socket IDs, and serializes Laravel query parameters. Its [saved-view composable](/Users/mwallner/Development/products/kit/resources/js/composables/useSavedViews.ts) calls REST resources and references `App.Data` types. These are observed Laravel dependencies, not reusable Holocron transport behavior.

Replace the client with a generic generated command/query client following the [typed client](contracts/architecture-patterns.md#typed-client) and [schema export](contracts/architecture-patterns.md#schema-export-and-drift-check) patterns. Wire types, operation names, IDs, argument/result maps, error codes and event frames come from Rust. Handwritten resource modules group those operations for callers. Pages and presentational components use resources/composables; transport code owns network calls.

Replace Kit's `App.Data.*`, generated Laravel abilities, REST paths, Echo/reactive transport, Blade boot configuration and Laravel validation shape. Map server errors into typed field messages at the resource boundary. Keep same-origin dashboard sessions and mutation protection in the Rust API contract. The unchanged modern Umami collector/recorder remains a separate cross-origin surface; dashboard command protections must not accidentally govern collection.

Use [Folio's service boundary](/Users/mwallner/Development/products/folio/apps/web/src/services/workspace.ts) and [thin Vue adapters](/Users/mwallner/Development/products/folio/apps/web/src/composables.ts) for exploration behavior. The exploration service owns normalization, serialization and state operations. It contains no server-result cache, browser event database, CRDT or offline sync. Vue Query owns server-result caching.

Completion criterion: the extracted frontend builds independently of Kit, contains no Laravel-generated types or Laravel/Echo endpoint calls, and its generated Rust types pass a drift check.

## Header and navigation

The context header follows the supplied Clerk-style reference without adding Clerk authentication or a new infrastructure dependency. Arrange compact workspace, website and environment context controls left to right, separated by slashes. Use a small context badge and paired switch chevrons. Keep the user menu at the far right.

Workspace context represents the authorized personal/team ownership context. Website context names the active website. Environment context is illustrative in the current example: do not invent environment tables, runtime partitioning, or an extra service. If no real environment setting is defined by the product contract, omit the selectable environment control. A static context badge must not look selectable.

Use Kit's Button and DropdownMenu/Popover primitives for context selection. Each selector has a full accessible name, a visible current value, keyboard selection, an active marker and an explicit empty state. Long names truncate visually while remaining available to assistive technology. Scope switching navigates once, cancels obsolete requests and clears unauthorized cached results before showing the new context. Selection uses server-authorized options, not a client-side list of assumed memberships.

The right-hand AppUserMenu retains the small avatar and chevron trigger, then identity, account links, appearance, locale, shortcuts and sign out. Sign out closes subscriptions and removes cached account/site results. Permission-sensitive menu items follow server-provided capabilities. Website settings belong in site navigation; personal account settings belong in this menu.

Desktop navigation groups the full analytics scope into understandable contextual sections rather than a top-level tab for every report. Keep active route and collapsed-rail tooltips clear. Mobile uses the adapted drawer and bottom navigation to reach the same routes. User identity, account links and context selectors do not appear a second time at the sidebar bottom.

## Tokens and geometry

Use `bg-sidebar` for header/sidebar/tab bar/drawer; `bg-surface` for canvas; `bg-card`, `border-border` and `shadow-soft-sm` for data panels; `bg-popover` and `border-popover-border` for floating controls. Modal dimming comes from Kit's `overlayClass`. Text uses primary, foreground and muted semantic roles. `muted` is a text color; `muted-background` is a fill.

Preserve Kit's 15px base type, its 8px base radius and its component radius variants. Standard shell tokens are `--shell-header-height`, `--shell-rail-width`, `--shell-gutter`, `--shell-gutter-x`, `--shell-row-height`, `--shell-row-gap` and `--shell-tabbar-height`. Kit defines standard header height as 3.5rem and compact as 3rem; use the density mechanism rather than local page overrides. Sidebar resizing must preserve the header's container-responsive behavior.

Use outline/ghost controls for secondary actions and one clear accent action where the page has a primary intent. Numerical columns use tabular figures and consistent alignment. Avoid local palette shades, arbitrary competing font scales and page-specific control sizes. Extend the shared stylesheet only where analytical graphics need semantic series tokens absent from the inspected primitives. Define current/comparison series centrally and distinguish them through marks, line style and labels as well as color.

## Exploration and table state

Use the versioned exploration contract from the technical briefing as the one state passed to URLs, saved views, board cards, exports and query keys. Generated state includes site, measures, dimensions, typed grouped predicates, relative/absolute dates, timezone, granularity, comparison, metric version, ordering, visualization and pagination. Workspace authorization context belongs in request/cache scope; it does not create a second analytical state model.

Normalize state before serialization or equality checks. Use stable predicate IDs so two conditions on the same field remain independently editable. Preserve grouping when changing views. Field/operator/value options come from an explicit supported capability model. A view that cannot support a predicate shows why it cannot run, rather than dropping the predicate. A URL with invalid or unsupported state shows a recoverable message and offers an explicit reset; it does not silently calculate a different report.

The service exposes concrete operations for include, exclude, split by, set date/comparison, choose measure, change visualization, clear filters, reset view and restore saved exploration. Bind the adapted TableFilter and FilterChip to these operations. Group editing uses Kit's Popover/Dialog/Sheet controls and exposes AND/OR labels. All committed edits produce one intentional browser history entry. Temporary field/operator/value input stays local until committed. Debounced text search follows Kit's 300ms starting convention. Replace navigation only for canonicalization, not for deliberate drilldowns.

Clear filters preserves date, dimensions, measure and visualization. Reset view is a separate action. A drilldown resets incompatible pagination while preserving all other compatible state. Browser Back restores the prior exploration without an additional refetch caused by duplicate watchers. Components derive active state from the service/router adapter rather than synchronizing independent copies.

Saved exploration controls retain Kit's active check mark, accessible current-view name and inline naming. Saving captures the complete normalized state. A relative range stays relative unless the person chooses a fixed range. Reopening and pinning a view preserve predicates, dimensions, comparison, timezone and metric version. Board cards visibly identify any local overrides. Changes to metric policy do not silently reinterpret saved definitions.

Use Table, TableSortableHead, TableEmptyRow, TableLoadingRow, PerPageSelect, TableSortSelect and the wrapping TableToolbar where appropriate. Management lists may use a smaller `useTableQueryState` adapter with generated sort IDs. Analytical tables never apply Kit's flat Laravel filter encoding. Server paging/sorting and allowed dimensions belong in the typed contract. Do not download a full dataset to paginate it in the browser.

Tables expose a named include/exclude/split-by action on breakdown values. Sorting controls retain header semantics. Row action menus have labels naming the row. Distinguish an empty website, no matching data, permission refusal and unavailable calculation. Keep count precision, currency, percentile and metric-version descriptions consistent with server results.

## Queries, live state and freshness

Historical reports use Vue Query keys containing resource/operation, normalized exploration, authorization scope and dataset watermark or refresh epoch. Include every argument that changes the result. Resolve relative time once per request; display the response's resolved interval and timezone. Use the server-reported committed analytical watermark and calculation version, not a SQLite control revision, to describe analytical freshness.

Pass AbortSignal through resources to transport. Cancel abandoned requests and use state generations so delayed results cannot replace another site or exploration. Retained previous data is acceptable only when clearly labelled as the previous result while updating. Never show another authorization scope's data as placeholder content. On authorization change/sign out, dispose subscriptions and remove restricted caches.

Kit's [Vue Query defaults](/Users/mwallner/Development/products/kit/resources/js/plugins/vue-query.ts) use five-minute stale time and thirty-minute collection time. These are observed starting defaults, not analytical freshness promises. Configure resource-specific refresh behavior. Avoid automatic duplicate long-range queries on focus; refresh historical results on a deliberate refresh epoch or the defined cadence. Retry transient transport failures within a bounded policy; permission and argument failures immediately surface their recovery action.

Realtime, import progress and processing lag use authorized snapshot/subscription adapters following the [subscription and live snapshot adapter](contracts/architecture-patterns.md#live-snapshot-adapter) patterns. The live-snapshot adapter reloads once per affecting event batch. It does not derive arbitrary analytical totals from event deltas. Historical queries are not invalidated for every collected event.

Expose connecting, disconnected, resynchronizing, stale and current states. Resume from the last cursor; an expired cursor fetches a fresh authorized snapshot. A server refusal closes the resource and removes restricted content. Keep the last authorized snapshot visibly stale only while access remains valid. Do not claim atomic snapshots across SQLite and DuckDB.

## Accessibility, responsive behavior and copy

Keep Kit's SkipLink, named main region, visible focus rings, reduced-motion rules and shared overlay behavior. On a page-route change focus the main region and announce the translated page title. On a filter/date/query edit in the same view preserve control focus; adapt AppLayout's broad afterEach handler rather than moving focus away after every exploration edit. Restore focus to the trigger when menus/dialogs close.

All exploration, board and recording actions work with a keyboard. Menus support arrow navigation and Escape. Filter controls announce committed additions/removals without announcing every keystroke. Provide drag alternatives for board ordering. Charts include a named accessible summary and a semantic data table with equivalent values. Tooltip-only and hover-only actions are insufficient. Financial or identity coverage information remains readable without relying on color.

At narrow widths selectors shorten visually, controls wrap, measures form a smaller grid and tables scroll within a labelled region rather than making the entire page overflow. Keep the search/filter input usable, following Kit's compact chip popover behavior. Respect safe-area padding above the header and below the mobile tab bar. Compare values, overflow menus and save controls remain reachable with long German labels and long website names.

Follow Kit's [typed i18n plugin](/Users/mwallner/Development/products/kit/resources/js/plugins/i18n.ts): derive MessageKey from English keys and type labels in navigation, field metadata and metric definitions with it. Write English and German together and check key parity. Use exhaustive maps for generated metric/operator enums instead of unchecked runtime string composition. Translate accessible names, failures, empty/loading states and notifications. Format dates/numbers/currencies with locale-aware formatters and the selected analytical timezone. Raw user event/property values remain data, escaped as text rather than translated or rendered as HTML.

Label multi-day anonymous figures as visitor-days and duration as observed span. Retention/cohort screens identify the consented identified population and its coverage. Imported identity limits, recording expiry/caps and unavailable results have explicit copy. UI wording cannot imply full-person continuity, active attention, unsampled recording or corrected totals before recomputation completes.

## Visual and interaction acceptance

Verify the rendered production Vue surface, not just its diff. Use the product-native preview tools when available. Capture light and dark views at 1440px, 1024px, 768px and 390px, plus a zoom/reflow check. Inspect standard and compact density, expanded/collapsed sidebar, longest supported context names and German copy. These are validation cases, not additional product settings.

For the Roadhouse overview retain five summary measures, the hourly chart, pages/referrers and browser/OS/device tables. Contextual navigation replaces top-level tab clutter. Global exploration controls sit above the measures, with date, selected measure, comparison, filters and freshness visible together. Use the example's layout direction while calculating real results through the typed backend.

Completion requires the following demonstrated outcomes:

1. Workspace/site switching, user menu, keyboard navigation and mobile drawer work without exposing another scope's data. Account navigation is absent from the sidebar.
2. The briefing's last-30-days/mobile/signup/plan=pro/country/referrer workflow can be completed, saved, pinned and reopened. Repeated-field predicates and AND/OR groups survive URL roundtrip and Back.
3. Fast edits with delayed server responses show the latest exploration only. Loading, previous-result, empty, invalid-state, permission, network and recomputation states are distinguishable.
4. Charts and equivalent tables agree on values, dates, versions and scope. Freshness reflects server watermarks. Reconnect and cursor expiry restore live resources without refetching every historical panel.
5. Light/dark, phone and zoom checks show no clipped controls, hidden final rows, conflicting surface tones or broken hover/focus states. Test keyboard flows and an automated accessibility pass alongside visual inspection.
6. Targeted frontend typecheck/lint, generated-type drift, locale parity, exploration-state tests and browser journey checks pass. Document a check that cannot run and its concrete blocker. Do not treat the static overview example as production verification.

Write focused tests for state normalization, URL/saved-view roundtrip, repeated predicates/groups, cancellation/scope changes and cursor recovery. Browser journeys exercise the interactions above. The implementation stages in the technical briefing remain the release plan; frontend staging does not remove any agreed analytical feature.
